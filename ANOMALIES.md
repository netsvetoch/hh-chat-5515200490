# ANOMALIES: `data_pack/review.csv`

Контекст: CSV позиционируется как «свежая выгрузка для той же базы», что и `page_*.json` (1000 строк, id `c_000001`…`c_001000`, 994 unique). Ниже — что не так и как обнаружено.

## 1. Это не обновление той же базы

| Проверка       | JSON (`page_*.json`)  | CSV (`review.csv`)                                                                       |
| -------------- | --------------------- | ---------------------------------------------------------------------------------------- |
| Строк          | 1000 (994 unique id)  | 207 (205 непустых, 202 unique id)                                                        |
| Диапазон id    | `c_000001`–`c_001000` | в основном `c_001001`–`c_001190` + `c_900006`–`c_900011`                                 |
| Пересечение id | —                     | **только 6** id (`c_000098`, `c_000246`, `c_000263`, `c_000425`, `c_000769`, `c_000851`) |
| Только в CSV   | —                     | **196** id                                                                               |

**Как обнаружено:** сравнение множеств `id` после `json.load` всех `page_*.json` и `csv.DictReader` для `review.csv`.

Вывод: это не refresh тех же компаний, а другой (меньший) набор + хвост «чужих» id. Название файла `review` тоже не про отзывы — внутри те же поля компании, что в JSON.

## 2. Грязные / невалидные значения (схема БД их отвергнет)

Схема: `rating NUMERIC(2,1)`, `reviews_count INTEGER CHECK (>= 0)`, `name/category/city NOT NULL`.

| Строка CSV (1-based + header) | id         | Поле          | Значение                      | Почему плохо                   |
| ----------------------------- | ---------- | ------------- | ----------------------------- | ------------------------------ |
| 9                             | `c_001083` | rating        | `N/A`                         | не число                       |
| 14                            | `c_001010` | rating        | `4,5`                         | запятая вместо точки           |
| 61                            | `c_001116` | reviews_count | `-10`                         | отрицательное → CHECK          |
| 96                            | `c_001122` | rating        | `-3`                          | вне шкалы 0–5 (и бессмысленно) |
| 98                            | `c_001079` | reviews_count | `45.5`                        | не integer                     |
| 130                           | `c_001064` | site          | `нет сайта`                   | текст вместо URL/NULL          |
| 141                           | `c_001020` | site          | `htp://sintez-service-453.ru` | опечатка схемы (`htp`)         |
| 197                           | `c_001186` | rating        | `7.2`                         | выше 5.0                       |
| 200                           | `c_001187` | reviews_count | `много`                       | не число                       |
| 207–208                       | _(пусто)_  | все           | пусто                         | 2 пустые строки в конце файла  |

**Как обнаружено:** проход по строкам, `float()`/`int()` с перехватом ошибок, проверки диапазонов и префикса URL.

В JSON таких битых значений нет: `rating` float/null, `reviews_count` int ≥ 0, `site` url/null.

## 3. Дубликаты id внутри CSV

Полные дубликаты строк (2× каждая):

- `c_001075`
- `c_001049`
- `c_001050`

Плюс 2 пустые строки с пустым `id`.

**Как обнаружено:** `Counter(ids)`.

## 4. Подозрительные id `c_900006` … `c_900011`

Шесть записей с номерами ~900000 — далеко от основного ряда (~1000–1190). Похоже на тестовые/sentinel-id, вставленные в «боевую» выгрузку.

**Как обнаружено:** `max(id_num)` и фильтр `id_num >= 900000`.

## 5. Расхождение объёма с заявленным «той же базой»

JSON: `total: 1000` в каждой page-мета. CSV: ~200 компаний. Даже как delta///append это не документировано; 196 новых id при 6 совпадениях — не «свежий снимок», а другой dump.

## 6. Мелочи качества

- Пустой `rating`: 18+ строк (в JSON тоже бывает null — ок, но рядом с `N/A`/`4,5` выглядит как смешанный ручной export).
- Пустой `phone`: ~20 строк.
- Дубликаты в JSON (6 id) — известная особенность основного dump; к CSV не относится, но при «слиянии» с CSV пересечение 6 id совпадает по полям 1:1 (не обновление, а копии).

---

## Итог

`review.csv` **нельзя** считать чистой свежей выгрузкой той же базы: почти нет пересечения id, другие диапазоны id, битые типы, дубли, пустые строки и id `c_90000x`. Похоже на отредактированный/тестовый фрагмент или чужой export, подложенный рядом с основным data pack.
